# Keep My Car - Product Baseline

## Concept

「好きな車に、あと何年乗れる？」

愛着のある車を長期保有したい人向けの、未来型カーライフ・長期保有コストプランナー。

中心価値は**「愛車と過ごす未来を見通す」**。愛車を保有目標まで乗る場合の車齢、想定走行距離、登録済み予定費用を把握するための製品とする。来年に必要になりそうな費用や数年後の整備予定、保有目標年齢のころの愛車の姿を見通せることを重視する。何年乗れるかを保証するものではなく、未登録の費用まで含む完全な総維持費・総所有コストを示すものでもない。

本Baselineでは現在のStep 15方針を優先する。Step 13以前の判断は履歴として維持し、Step 15で見直した内容を現在の有効なMVP要件と混同しない。詳細な承認済み仕様・工程・実装記録は [current_step.md](current_step.md) を正本とする。

## Target

主に40～70代。特に、愛着のある車を長く所有したい人や、以下の車の所有者。

- 輸入車
- スポーツカー
- 趣味車
- 旧車
- 高額修理リスクのある車

## Product Philosophy

- 愛着のある車を保有目標まで乗り続ける場合の、予定費と自分・愛車の未来の見通しをつくる
- 利用者に積立計画を強制しない。大型修理への備えや月額積立試算を製品の中心に置かない
- 普通の車計簿にはしない
- 故障予測は行わない。故障時期や故障確率をアプリが予測する機能はMVP対象外とする
- 故障時期や故障確率を根拠なく断定せず、ユーザー入力に基づく予定費と客観的な故障予測を混同しない
- 大型修理ストレステストや仮想シナリオは故障予測とは区別し、将来の検討候補として維持する
- 安心度Score等を乱用しない
- 一人で無理なく長期維持できる製品とする
- 固定費、クラウド費、運用負荷、サポート負荷を小さくする
- 小規模な開発・運用を維持し、一人で長期保守できる構成を選択する
- 利用者の個人情報をサーバに保存しない設計を優先する
- 既存データの安全性とバックアップ互換性を守る

## MVP Core

- Home：保有目標と予定費の見通しを起動直後に把握する
- 未来タイムライン：保有目標までの自分の年齢・車齢・想定走行距離・予定費を確認する
- 愛車予定費の登録・編集・削除：未来の見通しをつくるための入力・管理
- 保有目標設定：現在の走行距離・年間走行距離・保有目標年齢を中心とする

設定の3項目を中心にすることは製品方針であり、現行設定画面の実装変更済みを意味しない。大型修理関連項目の非表示化・必須入力解除・入力検証の依存関係整理、初回設定の見直しはStep 15-Eで扱う。現時点では既存保存値を保持する。

予定費の追加・編集・削除はMVP中心機能として維持する。ただし保有目標到達済みの場合、新規追加・既存変更を一時的に制限し、目標を見直した後に行う。見直し後も既存の予定年月の入力検証が適用され、追加・変更の可否は見直し後の有効期間と予定年月によって決まる。既存予定費の閲覧・確認・削除は可能とし、削除確認を維持する。具体的な画面仕様は [current_step.mdのStep 15-D](current_step.md) に従う。

## MVP必須基盤

- ローカル保存
- 手動バックアップ・復元（Manual Export / Import）
- 基本入力検証
- オフライン利用
- 決定論的な数値計算

## MVP再検討対象

- 大型修理への備え
- 月額積立試算

MVPでの必要性を再評価する補助機能候補とし、採否と位置付けはStep 15-Eで判断する。既存のRepair Reserve画面・計算・保存データはこの段階で削除しない。設定画面や初回設定に残る関連入力、保有目標との検証依存、月額積立計算、データ互換性も同工程で整理する。

## 将来候補

- 大型修理ストレステスト
- 修理して維持する場合と買い替える場合の費用比較

構想は維持するが、MVPでの実装を約束しない。必要性・採否は別途判断する。過去のHome内表示だった「積立額の決め手」は、独立画面ではなく現在の通常UIにも存在しないため、MVPへ復活させない。関連未使用コード・Golden Sample固定期待値の整理は、既存テストと承認済み仕様への影響を確認する別作業とする。

## 原則MVP対象外

- GPS走行記録
- OBD連携
- SNS
- クラウド同期
- AI機能

## 過去の判断と現在の優先関係

Phase 05 Step 13では、当時の中核を所有者情報、愛車情報、保有目標、現在の愛車専用資金、将来の予定費、未来タイムライン、大型修理への備え、必要積立額、安全なローカル保存、Manual Export / Importと整理し、「将来の維持・修繕資金計画」をMVP価値としていた。当時は大型修理予備費の積立機能を維持し、複数シナリオ専用比較UIを初回MVPから外した。これは過去の判断履歴である。

現在の中心価値・MVP優先順位・大型修理と月額積立の扱いは本書と [current_step.mdのStep 15](current_step.md) を優先する。Step 13の「大型修理・必要積立額を中核として維持する」という方針を、現在も必須の中心機能であると解釈しない。フルTCOの完成を要求しないこと、保存安全性・手動バックアップの必須要件、その他Step 15で変更していない有効な方針は継承する。

初回リリース範囲・除外項目・将来候補・ロードマップは [current_step.md](current_step.md) を正本とし、Step 13の記録とStep 15による見直しを区別する。製品名・キャッチコピーと過去の構想は維持し、将来候補を実装確約とはしない。

## 費目入力

- 費目名称は自由入力とし、「その他」というまとめカテゴリを設けず、各費用を具体的な名称で管理する。
- プリセット候補＋自由入力、車検周期選択、必要に応じた繰り返し／周期登録の構想は維持する。Step 13で初回MVPには要求せず、リリース後に必要性を再評価する候補とした。
- プリセット候補：タイヤ、ブレーキ、バッテリー、オイル、プラグ、サスペンション、エアコン、ブッシュ、電装品、アクセサリー、コーティング、法定12ヶ月点検。
- 車検周期の構想は全ユーザー一律の固定2年とはせず、必要に応じて選択できる方向とする。周期専用機能の採否はリリース後の再評価対象とする。

これらの将来構想・リリース後の再評価候補と実装済み範囲は区別する。現在の実装状態は [current_step.md](current_step.md) を参照する。

## Backup / Data Portability

- ユーザーデータの手動Export（エクスポート）と手動Import（インポート）は、MVP全体のMUSTとする。
- 長期利用、端末故障・紛失への備え、および機種変更時のデータ移行を目的とする。Android → Android、iPhone → iPhone、Android ⇔ iPhoneのデータ可搬性はMVP全体のMUSTとして維持する。
- Step 13判断として、初回Android MVPではiOSアプリ自体の実装は要求しない。OS固有形式に閉じないversion付きの論理Export形式を用い、後続のiOS実装でも同じ論理形式をImportできる設計によって将来互換性を担保する方針とする。詳細仕様・受入条件は [current_step.mdのStep 14](current_step.md) を正本とする。
- 現在はWindows開発であり、iOSはAndroid初回MVP後、Mac導入後に進める後続プラットフォーム工程とする。必要性そのものを再評価する任意機能とは区別する。初回Android MVP完成のブロッカーにせず、Android版完成をMac購入まで止めない。実際のApp Store公開時期はその時点で改めて判断する。
- 基本方向はローカル保存＋ユーザー操作による手動Export / Importとする。自動クラウド同期は初回MVPから除外する。
- MVPは引き続き原則サーバなし、ユーザーアカウントなし、クラウド認証なし、個人情報のサーバ保存なしとし、可能な限りオフラインで利用できるものとする。

MUSTは製品要件であり、実装済みを意味しない。現在の実装状態は [current_step.md](current_step.md) を参照する。

Step 12の内部 `current / temp / backup` はSafe Save用であり、ユーザーが持ち出せるManual Export / Importとは別物である。Manual Export / ImportはStep 14で扱うMUSTであり、Importは既存データを壊さない安全設計を前提とする。

内部保存方式・保存DTO・Safe Save / Recoveryは `current_step.md` のStep 12、外部Export形式・version・拡張子・暗号化方針・Import validation・破損ファイル対応は同文書のStep 14に従う。本Baselineには詳細仕様を重複記載しない。

Step 15の情報設計変更ではPersistence形式・Backup v1形式・保存項目を変更しない。大型修理関連項目を画面上の主役から外しても既存保存値を保持し、復元後に自動削除したり予定費へ自動変換したりしない。
